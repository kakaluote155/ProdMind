# ProdMind v0.1 Implementation Plan

## Objective

Prove one complete production-support loop:

```text
User performs an action
        ↓
Action fails
        ↓
ProdMind identifies the request/trace
        ↓
Collects correlated evidence
        ↓
Builds a root-cause explanation
        ↓
Returns a customer-safe answer and an engineer report
```

## Definition of done

v0.1 is complete when the demo application can reproduce the following flow without manually pasting an exception into ProdMind:

1. User attempts to create a duplicate account.
2. Demo backend emits an OpenTelemetry trace and correlated application log.
3. Browser/widget retains the request/trace context for the failed action.
4. User asks: `Why did creating the user fail?`
5. ProdMind retrieves the trace and related logs automatically.
6. ProdMind identifies the database unique-constraint violation.
7. Customer receives a safe business explanation.
8. Engineer receives the evidence chain and technical root cause.

## Work packages

### A. Action Context SDK

- Capture page, action, timestamp and request ID.
- Read trace context from response headers where available.
- Keep only recent actions in memory/session storage.
- Never capture arbitrary form payloads by default.

### B. Demo application

- Small frontend with create-user flow.
- Spring Boot or lightweight service backend.
- PostgreSQL users table with unique phone constraint.
- Intentional duplicate-user scenario.

### C. Observability

- OpenTelemetry instrumentation.
- Tempo for traces.
- Loki for logs.
- Prometheus for metrics.
- Correlate logs using trace ID.

### D. Investigation engine

- Start from action context.
- Resolve trace.
- Locate failing span.
- Fetch correlated logs.
- Normalize evidence.
- Run deterministic signatures before any LLM reasoning.

### E. Response policy

- Customer view: business-safe explanation only.
- Engineer view: technical evidence.
- Redact secrets and infrastructure details from customer output.

## Non-goals for v0.1

- automatic production remediation
- Kubernetes support
- dozens of observability vendors
- source-code patch generation
- autonomous shell execution
- vector database requirement

Keeping these out of v0.1 is intentional. The first release should prove trustworthy investigation before expanding the surface area.
